# Reconstructed breast-cancer gene-pair workflow (version 3)

`SpaGI-BC` is retained here solely as a historical internal project/version label. No verifiable formal expansion or corresponding published method was found, and it should not be conflated with the unrelated 2018 SPAGI method. Similarly, `sDDS` is retained in legacy variable, function, and file names only for reproducibility; the auditable output is the predicted probability of the relative assay-defined sensitive class, not a patient-benefit probability.

**Public-release note:** this repository intentionally excludes frozen model objects and record-level derived tables because their upstream GDSC, KEGG, cBioPortal, GEO/SCP, or clinical-data terms require source-specific treatment. The prediction examples below describe the complete internal archive; they will run only when the author has supplied an eligible local model bundle and authorised source inputs. See the repository-root `THIRD_PARTY_NOTICES.md`.

This release contains the executed analysis logic with filesystem configuration made explicit. Original large datasets are not bundled. Final-model prediction and full reconstruction have different input requirements. These research models are not validated for clinical use.

## Environment

Use the R/package versions in `software_versions_v3.csv` and `sessionInfo.txt`. The spatial recipe additionally requires the Scanpy/AnnData environment recorded in `spatial_python_versions.txt`; do not silently upgrade it if reproducing frozen region membership. `code/legacy_provenance/` contains provenance scripts, not the v3 execution path. The public phase-1 copy externalises the sample-label/subtype map through `SPAGI_SUBTYPE_MAP`; the exact executed script and mapping remain in the authors' controlled internal audit archive.

Run commands from the unpacked package root, using Bash environment variables:

```bash
export SPAGI_CODE_DIR="$PWD/code"
export SPAGI_OUT="$PWD"
export SPAGI_ROOT="/absolute/path/to/data/SpaGI_BC"
export SPAGI_WORK="/absolute/path/to/work-v3"
export SPAGI_CHECKPOINT="/absolute/path/to/checkpoints-v3"
export SPAGI_GENCODE="/absolute/path/to/gencode.v44.annotation.gtf.gz"
export SPAGI_KEGG="/absolute/path/to/kegg_2021.json"
export SPAGI_SPATIAL_SOFT="/absolute/path/to/GSE213688_family.soft.gz"
export SPAGI_PYTHON="/absolute/path/to/scanpy-environment/python"
```

Use a separate output copy/directory when rerunning; analysis stages overwrite their own versioned output filenames. Never overwrite v2. `SPAGI_WORK` must be local/POSIX storage for random-access working formats. On object-backed mounts, completed DOCX/ZIP files are staged locally and copied with shell `cp`, not R `file.copy`.

## Inputs

`input_manifest_v3.csv` records portable `SOURCE_ROOT` locators, relative paths, byte sizes and SHA-256 values; machine-specific source paths have been removed. Recreate the listed hierarchy under `SPAGI_ROOT`: `00_raw_data/`, `01_scRNA_processed/`, `02_GI_networks/`, `03_TME_extrinsic_SV/`, `04_sDDS_model/`, `05_spatial_niche/` and `06_clinical_validation/`. The saved propR table is the authoritative association source, not a reimplementation of its original inference.

Place the GENCODE GTF and KEGG JSON at the configured reference paths. The old tripartite table, old spatial spot/summary files and frozen signatures are needed only for provenance/reproduction gates, never as substitutes for rebuilt scores.

`checkpoint_inputs.R` optionally copies the source inputs to checkpoint storage; it requires the legacy provenance scripts as listed. Its copy step is not itself verification. The final audit independently checks bytes and hashes. The clinical reference stage may fetch bounded missing-gene records and official sample manifests from cBioPortal for the same existing METABRIC/TCGA cohorts; verified cached records can be restored into the working directory to avoid network refetch.

The network stage also rebuilds modules. Full atlas raw input is sparse and must not be densified; atlas drug scoring uses 250-cell chunks. Native model training is restricted to two threads. During an authorised rerun, models and fold objects are written to the configured working/checkpoint directories. This public release does not include those objects or the record-level input/output files required to recreate them.

`figures` uses Figure 1 generated by the authors' archived phase-1 workflow from public GSE176078 count matrices and carried forward unchanged into v3; it is not copied or adapted from the Wu et al. publication. Optionally set `SPAGI_FIG1_DIR` to another verified copy. Figures 2–6 require the stage objects in `SPAGI_WORK`, as well as the exported CSVs. Model-level reuse does not require rerunning the atlas.

## Prediction interface (local eligible model bundle required)

```r
Sys.setenv(SPAGI_CODE_DIR = normalizePath("code"))
source("code/sdds_interface.R")
fit <- readRDS("models/sDDS_Paclitaxel_v3.rds")
bundle <- fit$bundles$xgboost_weighted

# X: numeric matrix, samples in rows, unique human gene symbols in columns.
# Supply real expression values, not cohort-centered z scores.
# Resolve identifiers and duplicate symbols as documented before prediction.
# Log or linear input should preserve within-sample gene ordering.
pred <- predict_sdds(bundle, X)
pred[, .(sample_id, coverage, status, probability_sensitive)]
```

Coverage is computed over the frozen 13,357-gene U, not just the pair partners. A small gene-panel matrix cannot be used to bypass the 95% rule. Measured zeros are values; unmeasured genes should be absent/NA, not filled with zero. The API returns NA probabilities for rejected coverage. It never learns new centering/scaling or target-cohort calibration.

In the complete internal analysis archive, `fit$bundles` also contains `xgboost_unweighted`, `elastic_net_weighted` and `elastic_net_unweighted`. Do not compare training-fit predictions with held-out metrics. No `models/` directory or frozen model object is redistributed in this public release; the example runs only after an author has supplied an eligible local bundle.

## Clinical-model interface (objects not redistributed)

In the complete internal archive, `pCR_frozen_models_v3.rds` stores `final$M0/M1/M2`, each with its fitted ridge model and clinical preprocessor, and `clinical_reference_v3.rds` stores the rank-NNLS basis, U_ref, module/T-cell lists and full I-SPY training module moments. Those objects are not redistributed here because they embed record-level identifiers or source-derived parameters. The delivered scripts retain the reconstruction logic for authorised users with eligible source access.

Clinical ESV is a separately versioned bulk score; it is not numerically interchangeable with atlas/spatial ESV. NNLS outputs are relative composition proxies, not validated fractions.

## Audit and interpretation

- Seeds and fixed grids are in `parameters_v3.json`; the complete private audit archive preserves the record-level fold, out-of-fold, and label decisions, while this public release reports only eligible aggregate results.
- Primary AUROC is the mean of repeat-specific pooled OOF AUROCs.
- Conditional bootstrap CIs use AUROC of mean OOF predictions and do not refit models.
- Positive topology weighting yielded identical XGBoost predictions to its matched unweighted control.
- Familiar cell lines in cross-assay evaluation are scored only by outer models excluding that ModelID.
- Spatial donor independence is unresolved; pCR transfer is within I-SPY2; survival overall BH tests are negative.
- Pilot outputs are separated in `tables/pilot/` in the controlled internal archive; that directory is not redistributed in this public release and pilot results must not replace the final aggregate outputs.

The portable runner and prediction interface were smoke-tested against the complete internal archive, and the source files were syntax-checked. A second independent full-data retraining is not implied by those packaging tests. Verify every input hash and obtain all required data under their source-specific terms before rebuilding in a new environment.
